# Telemetry privacy during release cutover

The Data API release header and operator access code are credentials. Do not place them in URLs, logs, source, screenshots or tracing context. Provision them through the approved protected provider interface. This source change does not provision credentials or activate the database fence.

All three web Sentry runtimes use `lib/runtime/telemetryPrivacy.ts`. For the pinned SDK10.75.2, automatic collection explicitly excludes HTTP headers/bodies, cookies, URL query values, user information, GraphQL content, generative AI inputs/outputs, database query data and stack variables. Specify every supported category: opting into `dataCollection` changes defaults. These settings follow the installed declarations and [Sentry's collection options](https://docs.sentry.io/platforms/javascript/guides/nextjs/configuration/options/), checked Nov14,2026.

Explicitly attached context passes through the same scrubber for errors, transactions, spans, breadcrumbs and logs. It filters known credential fields case-insensitively, including flattened release-header attributes, request bodies/cookies/query strings, and URL credentials/query/fragment values. Traversal is bounded and does not mutate the original context. Method, status, error identity and timing metadata remain available. This follows [Sentry's separate hook guidance](https://docs.sentry.io/platforms/javascript/guides/nextjs/data-management/sensitive-data/). Existing replay masking remains configured separately; collection settings do not control Replay.

This is not a general detector of secrets or personal information in arbitrary prose. Never attach journals, raw requests, serialized credentials or customer records to error messages or arbitrary extra fields. No new logging, AI instrumentation, replay capture or trace sampling is enabled by this change.

The regression suite checks each actual runtime configuration and captures an event using the installed SDK with an in-memory transport. Synthetic credentials must be absent before the transport receives the envelope; no event is sent to Sentry. Cyclic/deep context and preservation of diagnostic metadata are also covered. Full exact-source CI/build and hosted configuration checks remain separate release requirements.

Supabase's [API log field reference](https://supabase.com/docs/guides/observability/log-field-reference), checked Nov14,2026, documents a captured-header allowlist that excludes the custom release credential. This establishes documented gateway behavior, not an audit of arbitrary external log drains. Review actual drains and integrations before activation, without querying raw headers or customer logs. Do not enable `pg_net` bearer dispatch; the existing worker design avoids its queued-header exposure.
