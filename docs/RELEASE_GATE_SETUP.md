## Rollback

Do not apply destructive down migrations. Stop incompatible consumers, retain queued jobs, receipt bindings and outbox records, and use a reviewed application version that understands the retained schema. Old web clients and old webhook handlers must be considered separately. Reverting code cannot establish which old completed payments received access.

The manual **Prepare Production Rollback** workflow now produces an untested revert patch tied to the current master SHA and an explicit single-parent commit. It has read-only permissions and cannot push or promote a deployment. Review the patch's retained-schema/payment compatibility, apply it on a feature branch, and pass the same release gate before merging. Merge-commit rollback requires a separately reviewed mainline choice. The previous direct master push and unspecified Vercel rollback shortcuts have been removed. Manual provider promotion remains an external entry point requiring exact-artifact review and delivery verification.
